# Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app for the owner to read risks in full, review them, and edit, manage, and
approve them, on the same core rules as `./tmreg`.

**Architecture:** tmreg's core gains the owner-decided edit rule and three read helpers. A
FastAPI back end in `webapp/backend/` calls one `Registry` method per request behind a
sign-in lock (one-time link, cookie, CSRF, host check). It serves a React + TypeScript + Vite +
Mantine front end from `webapp/frontend/dist/`. The guide is amended to match.

**Tech Stack:** Python 3.11+ (tmreg: stdlib only), FastAPI, uvicorn, pytest, httpx, uv; React,
TypeScript, Vite, Mantine, React Router, TanStack Query, react-markdown, remark-gfm, mermaid,
Vitest, Testing Library, jsdom, npm.

**Spec:** `docs/superpowers/specs/2026-11-08-web-app-design.md` (approved 2026-11-08). Read it
with this plan. Section numbers below (§) refer to it.

## Global Constraints

- tmreg stays Python 3.11+, standard library only. The web app's dependencies live only under
  `webapp/`, and nothing in `registry/` imports them.
- The guard stays Python 3.9+, standard library only. `make test` keeps working with no web
  dependencies installed.
- Every rule lives in `registry/tmreg/core.py`. The server parses a request, calls one `Registry`
  method, and returns the result or the `RegistryError` message. It validates nothing itself.
- No select-all, no multi-item endpoint, no approval without a note, approve only what was shown,
  every create lands pending.
- The server listens on `127.0.0.1` only.
- Dependencies are pinned to exact versions with lockfiles (`uv.lock`, `package-lock.json`). Use
  the latest stable release of each package at implementation time.
- No asset is loaded from the network at run time: no CDN, no web fonts, no telemetry.
- Text is never truncated on a risk's page. Dates show as absolute local times
  (`YYYY-MM-DD HH:mm`). AI and human authorship are always labeled. WCAG 2.1 AA.
- Risk data never enters git. Fixtures use sample data from the guide's reference system or
  `registry/tests/helpers.py` only. Never open `registry/registry.db` or `registry/trial.db`, and
  never run `./tmreg run start`, `add`, or `edit` against them.
- The server refuses to start in a Claude Code shell, by design, so Claude cannot run it.
  Verification is by tests. The owner does the end-to-end check (Task 15).
- Work on branch `feat/web-app` in `~/Developer/threat-models`. Stage files by name. Commit
  messages start with `feat:`, `fix:`, or `chore:` (guide: `content:` or `chore:`). Never use
  `--no-verify`. Never push.

## Review Focus

1. AI-written text containing markup, control characters, or bidi controls must display
   literally, escaped like the CLI's `visible()`, never as HTML or reordered text. Test: Task 8,
   `renders hostile text literally`.
2. Long text and many elements must show in full at any width, with no ellipsis or line clamp,
   and long unbroken strings must wrap. Test: Task 8, `shows a 5000-character field in full`.
3. A missing database, a missing trial register, a missing or invalid `dfd.md`, or a cited ID no
   longer in the DFD must show core's message or a clear label, never crash, and never create a
   database file. Tests: Task 5, `no database file is created`, `invalid dfd.md still shows the
   risk`, and `missing IDs are null`.
4. Acting twice or on a version you didn't see (a double click, two tabs, an AI edit landing
   while you read) must never write twice or act on the unseen version. Buttons disable while a
   request runs. 409 and 422 keep the typed note. Tests: Task 6, `second approve is refused`;
   Task 9, `busy disables every button` and `stale keeps the note`.
5. A server restart, or reusing a sign-in link, leaves an open tab with no session. Every page
   must then show the signed-out screen with how to sign in, not a broken page. Test: Task 7,
   `401 shows the signed-out screen`.

**Interfaces:**
- Produces, in `security.py`:
  - `class SessionStore`, built with `SessionStore(signin_token: str)`.
  - `SessionStore.consume(token: str) -> str | None` returns a new session ID once, comparing
    with `secrets.compare_digest`.
  - `SessionStore.csrf(session_id: str) -> str | None`.
  - `COOKIE = "tmweb_session"` and `CSRF_HEADER = "X-CSRF-Token"`.
  - `allowed_hosts(port: int) -> set[str]` gives `{"127.0.0.1:<port>", "localhost:<port>"}`.
  - `allowed_origins(port: int, dev: bool) -> set[str]` gives `http://` plus each allowed host,
    plus `http://localhost:5173` when `dev` is set.
- Produces, in `app.py`: `create_app(root: Path, *, port: int, signin_token: str,
  static_dir: Path | None = None, dev: bool = False) -> FastAPI`. It includes:
  - the lock middleware, in this order:
    1. any `Host` outside `allowed_hosts`: 400 `{"detail": "unknown host"}`;
    2. `/api/*` without a valid session cookie: 401 `{"detail": "signed out"}`;
    3. a non-GET or non-HEAD `/api/*` request without the matching `X-CSRF-Token` or with an
       `Origin` outside `allowed_origins`: 403.
  - `GET /signin?token=`: a valid token sets the cookie (`HttpOnly`, `SameSite=Strict`,
    `Path=/`) and redirects 303 to `/`. Otherwise 403 with the text "This sign-in link has been
    used or is not valid. Close the app's Terminal window and start it again for a new link."
  - `GET /api/session`: `{"reviewer": str, "csrf": str, "trial": bool}`. The reviewer comes from
    `config.load_project(root)`. `trial` is `(root/"registry"/"trial.db").is_file()`. No
    database is opened.
  - the SPA, when `static_dir` is set: `/assets` mounted, and a catch-all GET that returns
    `index.html`. Paths under `api/` return 404 instead.
  - `app.state.root`, `app.state.port`, and `app.state.sessions`, for later tasks' routers.
- Produces, in `__main__.py`: `main(argv: list[str] | None = None, *, root: Path = REPO_ROOT) -> int`.

  (default 8765) and `--dev`, then calls `core.require_interactive("web")` first. On
  `RegistryError` it prints the message to stderr and returns 1. Otherwise it makes the token

  `Sign in: http://127.0.0.1:<port>/signin?token=<token>` (with `localhost:5173` under `--dev`).
